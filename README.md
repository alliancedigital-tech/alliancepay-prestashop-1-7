# Платіжний шлюз AlliancePay для Prestashop 1.7.x

![AlliancePay Logo](https://alb.ua/_next/static/media/Alliance_logo.25cb4c66.svg)

## Огляд
Офіційний модуль платіжного шлюзу **AlliancePay** для **Prestashop**. Цей модуль дозволяє безперешкодно інтегрувати AlliancePay у ваш інтернет-магазин, забезпечуючи безпечний, швидкий та надійний процес оплати для ваших клієнтів.

## Основні можливості
* Безпечна обробка платежів через API AlliancePay.
* Підтримка різних валют та методів оплати Visa/Mastercard/GooglePay/ApplePay.
* Автоматична синхронізація статусів платежів (webhook / callback).
* Просте налаштування та зручний інтерфейс в адмін-панелі.

## Вимоги
* PHP 7.3 або вище
* PHP розширення: gmp, hash, openssl, sodium
* Prestashop версії 1.7.6.x+
* Активний обліковий запис мерчанта AlliancePay.

## Підпис запитів (JWS)
Запити мерчанта підписуються алгоритмом **ES256**: у налаштуваннях модуля потрібен приватний ключ **EC P-256** у форматі PEM (PKCS#8, `-----BEGIN PRIVATE KEY-----`), `kid` має відповідати цьому ключу. Алгоритм обирається за типом ключа: EC → `ES256`, RSA → `RS256` (для вже налаштованих встановлень). Ключ іншої кривої відхиляється з повідомленням про помилку.

## Фіскалізація
Модуль може фіскалізувати успішні операції PURCHASE (у тому числі рекурентні списання підписок) і REFUND через `POST /ecom/jws/cashbox/v2/fiscalization/create`.

**Налаштування** (розділ «Фіскалізація» на сторінці налаштувань):
* «Увімкнути фіскалізацію» — вимкнено: запити не надсилаються, кнопок немає.
* «Автоматична фіскалізація» — запит надсилається після успішного платежу/повернення (після відповіді банку, помилка фіскалізації не впливає на обробку платежу). Вимкнено — фіскалізація лише вручну, і для платежів, і для повернень.
* Значення за замовчуванням: код податкової групи (`taxCode`), УКТЗЕД (`classificationCode`, обов’язковий при `taxCode` 2, 7, 8), акцизні марки (`exciseLabels`), код одиниці виміру (`measurementCode`, за замовчуванням `0001`).

**Атрибути товару.** У формі товару (вкладка модуля «Фіскалізація») ті самі поля можна задати для конкретного товару; значення береться з товару, а якщо поле порожнє — з налаштувань, для кожного поля окремо. Значення на рівні комбінації зберігаються в таблиці, але форма комбінації поки не реалізована (TODO).

**Як це працює.** На сторінці замовлення, у вкладці AlliancePay, блок «Фіскалізація» показує кожну операцію зі статусом, фіскальним номером і посиланням на чек. Кнопка «Фіскалізувати» доступна, якщо запису ще немає або він у локальному статусі `ERROR`; «Оновити статус» — для `PENDING` та `FAIL` (повторно надсилає той самий запит, Ecom ідемпотентний за `operationId`). Результат приходить також callback-ом на `module/alliancepay/fiscalcallback` (підписаний JWS). Дані зберігаються в таблиці `alliance_fiscalization`.

**Типові помилки.**
| Код | Значення |
| --- | --- |
| `missing_required_field` / `invalid_format` | помилка в даних запиту, див. деталі в записі |
| `payment_not_found` | операцію `operationId` не знайдено в Ecom |
| `original_receipt_not_found` | для повернення спершу фіскалізуйте покупку |
| `NETWORK_ERROR`, `HTTP_5xx` | банк недоступний, повторіть кнопкою «Фіскалізувати» |
| `FAIL` + код (напр. `541`) | помилка Alliance Kasa; повторна відправка поверне те саме |
